Transformers from the top down

We began this module by considering the encoder and decoder as “black boxes”, studying what each can do on their own and together. We then began to open up these boxes to understand the role of different components. We have been gradually heading towards the figure of the transformer architecture presented in the original paper, Attention is all you need (Vaswani et al., 2017).

In this summary, we’ll revise this whole process, finishing by matching the diagram to a real model’s code. Specifically, we’ll be looking at Helsinki-NLP/opus-mt-en-de, a transformer for English-German translation based on the MarianMT model that is very close to the originally proposed Transformer.

The notation is the same as in lectures and in the paper: our input has $n$ tokens, the model dimension $d$, per-head dimensions are $d_k$ (keys/queries) and $d_v$ (values), and there are $h$ attention heads in each of $N$ layers.

The running example for encoder-decoder architecture is translating the cat sat on the mat into German. We’ll consider similar appropriate examples when discussing other architectures. All token IDs, attention weights and probabilities shown are real model outputs.

Encoder and decoder

  • A sequence-to-sequence transformer has two halves.
  • The encoder reads the whole input at once and outputs one vector per input token. Here there are $n = 7$ tokens, so it outputs 7 vectors, each of dimension $d = 512$.
  • The decoder takes the output so far, plus all of the encoder's vectors, and outputs a probability distribution for the next token.
  • To generate a longer text sample, we just pick a token, append it to the “output so far”, and run the decoder again.
  • Uses for this architecture include translation, summarisation, and question answering. Well-known models include the original Transformer, T5, the BART family, and the MarianMT English→German model we use here (74M parameters).

Encoder-only models

  • Some tasks don’t need textual output and therefore don’t need a full decoder. Instead, we can keep the encoder's per-token vectors and add a small task-specific head.
  • Here we illustrate a model for masked language modelling, where we predict a hidden token, indicated by the special token [MASK], using context from both sides.
  • We could apply other heads to the same encoder body, to perform tasks such as sentence classification, token classification, multiple choice, or embeddings for search.
  • Well-known models of this sort include the BERT family (BERT, RoBERTa, DistilBERT, ModernBERT).
  • The bars are real bert-base-uncased predictions for “the cat [MASK] on the mat.”

Back to the encoder-decoder…

  • We then recognised that the decoder on its own is already a language model: it predicts the next token from the tokens so far.
  • It just happens to also look at the encoder.

Decoder-only models

  • If we remove the encoder (and its link to the decoder), we get a causal language model, whose task is to predict the next token from the preceding ones only.
  • This is generally useful because almost any task can be phrased as continuing text, including translation (“English: … German:”), question answering, chat, and coding. Most frontier LLMs are of this type.
  • Decoder-only models can be pre-trained on huge amounts of raw text with no labels: every token becomes a training target.
  • Well-known models of this sort include the GPT family, Llama, Qwen, and SmolLM. We’ve used several of these in the labs.
  • The bars are real SmolLM2-135M probabilities after “The cat sat on the”.
  • We’re now ready to begin opening up the boxes, starting with the encoder.

Input embedding

  • The tokeniser splits text into subword tokens and maps each one to an integer ID. Here there are $n = 7$ tokens.
  • Using SentencePiece-type tokenisers, ▁ marks the start of a word.
  • The embedding layer is a lookup table containing one (learned) row of $d = 512$ numbers for each of the 58,101 vocabulary entries. (This is mathematically equivalent to multiplying a one-hot encoding by the lookup table as a matrix.) That adds up to 29.7M parameters, or 40% of this model. Here $d$ is called the model dimension.
  • The same token always gets the same row: for instance, both ▁thes get identical vectors. Context is added by the layers above.
  • Stacking the rows gives $X$, an $n \times d = 7 \times 512$ matrix. MarianMT (like the transformer paper) scales this matrix by $\sqrt{d} \approx 22.6$.

Positional encoding

  • Attention heads do not intrinsically record word order. There are various ways of explicitly including this information; here we present the one from the original transformer paper.
  • We add a position-dependent vector to each token's embedding. $\text{PE}$ is another $n \times d$ matrix, so our input is now $X + \text{PE}$.
  • This vector is determined by a fixed sinusoidal encoding: each of the $d$ dimensions is a sine or cosine of the position, with wavelengths that grow with the dimension number. Every position gets a unique pattern, and relative offsets are easy to detect.
  • The heatmaps are real MarianMT values. MarianMT puts all the sines in the first 256 dimensions and the cosines in the last 256; the paper instead interleaves them, but the purpose is the same.

One attention head: queries, keys, values

  • Each token's embedding $\mathbf{x}$ is projected three ways by learned matrices: the query $\mathbf{q} = \mathbf{x}W_Q$ (what am I looking for?), the key $\mathbf{k} = \mathbf{x}W_K$ (what am I useful to?) and the value $\mathbf{v} = \mathbf{x}W_V$ (what information do I give?).
  • These vectors can be simultaneously calculated for all tokens at once using matrix multiplication: $Q = XW_Q$, $K = XW_K$, $V = XW_V$. The same three weight matrices are used for every token.
  • $W_Q$ and $W_K$ are $d \times d_k$, and $W_V$ is $d \times d_v$. In MarianMT each head has $d_k = d_v = 64$, so $Q$, $K$ and $V$ are $n \times 64$: 7 tokens, each with a 64-dimensional query, key and value.

Scores and softmax

  • The score table $QK^\top$ is $n \times n$; the $(i, j)$ entry is $\mathbf{q}_i \cdot \mathbf{k}_j$, representing how well token $i$’s query matches token $j$’s key.
  • We divide by $\sqrt{d_k} = \sqrt{64} = 8$ so that the overall score is independent of $d_k$.
  • We then apply softmax along each row to convert the scores into weights that sum to 1.
  • We saw in class that this process is effectively a soft dictionary lookup.
  • These are real weights from MarianMT encoder layer 6, head 1. Each “the” attends strongly to its own noun.

Weighted sum of values

  • Output row $i$ is $\sum_j w_{ij}\,\mathbf{v}_j$: a context-dependent blend of the values.
  • In one line: $Z = \text{softmax}\!\left(QK^\top/\sqrt{d_k}\right)V$.
  • $Z$ is $n \times d_v$: one row per token ($n = 7$), each with $d_v = 64$ dimensions.

Multi-head attention

  • $h = 8$ heads run in parallel, each with its own $W_Q^{(i)}$, $W_K^{(i)}$, $W_V^{(i)}$, so each head can learn a different kind of relationship.
  • Each head works in a smaller space: $d_k = d_v = d/h = 512/8 = 64$.
  • Thumbnails: the 8 real heads of the same layer. Note the different patterns.
  • The $h$ outputs ($n \times d_v$ each) are concatenated into $n \times h d_v = 7 \times 512$, then mixed by one more matrix $W_O$ ($h d_v \times d = 512 \times 512$). The result is $n \times d$ again, the same shape as the input.
  • From now on, all of this is one “Multi-Head Attention” box.

Add & Norm

  • Residual connection (orange arrow): add the sublayer's input back to its output, $\mathbf{x} + \text{MHA}(\mathbf{x})$. The sublayer only has to learn a change, and information and gradients can flow straight through deep stacks.
  • Layer normalisation: rescale each token's $d$-dimensional vector to mean 0 and variance 1, then apply a learned scale $\gamma$ and shift $\beta$.
  • The paper and MarianMT normalise after the addition (“post-norm”): $\text{LayerNorm}(\mathbf{x} + \text{Sublayer}(\mathbf{x}))$. Many newer models (T5, GPT-2 onwards) normalise before the sublayer.

Feed-forward network

  • Two linear layers with a non-linearity between them: $d \to d_{ff} \to d$, i.e. $512 \to 2048 \to 512$.
  • Applied to each token separately, with the same weights at every position. Attention mixes information between tokens; the feed-forward network processes each token's vector.
  • It holds most of a layer's parameters: 2.1M, against 1.05M for attention.
  • Activation: ReLU in the paper; MarianMT uses SiLU (“swish”).
  • Then another Add & Norm. That completes one encoder layer.

Stacking layers

  • A layer takes an $n \times d$ matrix and returns an $n \times d$ matrix, so layers can be stacked.
  • MarianMT's encoder has 6 layers with the same architecture but their own weights. Each refines the token vectors using context gathered by the layers below.

The N× shorthand

  • The paper draws one layer and marks it N× ($N = 6$ in the base model and in MarianMT).
  • BERT-base has 12; large LLMs have 30 to 100+.

A masked-LM head

  • A linear layer maps each $d$-dimensional vector (512 here; 768 in BERT-base) to one score (logit) per vocabulary entry, and a softmax turns those scores into probabilities.
  • For masked LM, the loss is computed only at the masked positions.
  • BERT's real head adds a dense + LayerNorm step before the linear layer, and its output weights are tied to the embedding matrix.
  • For classification, swap in a linear layer to a few classes, applied to one token's vector (e.g. [CLS]).

The whole encoder-only model

  • Embedding + positions → N× encoder layer → head. That is essentially BERT.

Adding a decoder

  • For translation, we remove the head and connect a decoder. The encoder's output ($n \times d = 7 \times 512$) feeds every decoder layer.
  • The decoder uses the same building blocks, plus one new one.

Output embedding

  • The decoder's input is the target sentence shifted right: it starts with a start token (MarianMT uses <pad>, ID 58100), so position $i$ predicts token $i+1$.
  • During training the whole target is fed in at once: $n = 8$ tokens here, because “Matte” is split into ▁Matt + e.
  • The lookup is the same as before. MarianMT uses one shared matrix for the encoder input, the decoder input and the output layer.

Positional encoding, again

  • This works exactly as in the encoder: the same fixed sinusoids, now for 8 positions.

Masked self-attention

  • This is the same as encoder self-attention, except that each position may only attend to itself and earlier positions.
  • We achieve this by setting the scores above the diagonal to $-\infty$ before the softmax, so that their weights become 0.
  • Why? In training, all 8 positions are computed in parallel with the whole target present. Without the mask, position $i$ could simply copy token $i+1$. The mask makes training match generation, where later tokens don't exist yet.
  • This is MarianMT decoder layer 1, head 3: it mostly looks at the previous token.

Masked multi-head attention

  • We run $h = 8$ masked heads in parallel, then concatenate and apply $W_O$, exactly as before.
  • Shown are the 8 real heads of decoder layer 1. Note that each is lower-triangular, i.e., masked.

Add & Norm

  • This is identical to the encoder: a residual connection around the masked attention (orange arrow), then a normalisation step.

Cross-attention

  • We now have a second attention sublayer. Queries come from the decoder (the sublayer below); but keys and values come from the encoder output.
  • This is where the decoder “reads” the source sentence: each target position looks up the source tokens it needs.
  • The same encoder output is fed to all 6 decoder layers.

One cross-attention head

  • $Q$ comes from the decoder's $n_\text{dec} = 8$ tokens; $K$ and $V$ come from the encoder's $n_\text{enc} = 7$ tokens.
  • So the score table is $n_\text{dec} \times n_\text{enc} = 8 \times 7$. It isn't square, and there's no mask, because the whole source is known.
  • This MarianMT decoder layer 6, head 1. At each position it attends to the English word it is about to translate.

Feed-forward + Add & Norm

  • Again, this is the same as the encoder: position-wise $d \to d_{ff} \to d$ network, with a residual connection and normalisation.
  • A decoder layer therefore has three sublayers, each wrapped in Add & Norm.

Stacking decoder layers

  • 6 decoder layers. Each one receives the encoder output through its own cross-attention.

N×, again

  • Once again, we hide the details by simply writing N×.

Output head

  • Linear: $d \to$ vocabulary, i.e. $512 \to 58{,}101$ logits at each of the 8 positions. In MarianMT these weights are the shared embedding matrix again, plus a bias.
  • Softmax → probabilities. Training uses cross-entropy against the true next token at every position, all in parallel.
  • To generate text, we use the algorithms we studied in week 1. We choose a token, using an algorithm such as greedy, sampling, or beam search; append it; and repeat until </s>.
  • Shown are MarianMT probabilities at the position after “die Katze”.
