Tokenisation

We interpret text input as a series of tokens.

These will use a one-hot representation: that is, each token is represented by a vector that has value 1 in the position corresponding to a particular token and 0 everywhere else.

Each vector will therefore have length equal to our total vocabulary size.

Tokenisation

Each language model will have a different vocabulary and therefore a different approach to tokenisation.

  • Letters are probably too small: not enough meaning is conveyed within each, so the model has to combine many tokens to represent any concept.
  • Words are probably too big: English dictionaries might have up to 300,000 distinct words!
  • We can have an UNKNOWN token but only want to use this as a last resort.

Tokenisation

Let’s see how this looks for a small model in the Qwen series.

from transformers import AutoTokenizer
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2-0.5B")

prompt = "Once upon a"
input_ids = tokenizer(prompt).input_ids
input_ids
[12522, 5193, 264]

Our three words turn into three tokens.

for t in input_ids:
    print(f"{t:5d} --> {tokenizer.decode(t)}")
12522 --> Once
 5193 -->  upon
  264 -->  a

Note that the space is included in the subsequent token: e.g., token number 264 apparently represents " a".

Tokenisation

If we look at the raw vocabulary entries rather than the decoded text, that leading space is visible directly as a Ġ prefix:

tokenizer.convert_ids_to_tokens(input_ids)
['Once', 'Ġupon', 'Ġa']

For more on this sort of utility function, see https://huggingface.co/docs/transformers/v5.17.0/en/internal/tokenization_utils.

Tokenisation

  292 --> ic

Here the long word deoxyribonucleic is broken up into smaller tokens. Some (" de", "oxy") correspond to the semantic division of the English word, while others ("ucle") do not.

Interestingly, "DNA" is apparently common enough to be a token in its own right.

Special tokens

Tokenisers may also reserve tokens that indicate structure rather than a piece of text:

  • [PAD]: pads shorter sequences up to a common length so they can be batched together.
  • [BOS]/[EOS] (or <s>/</s>): mark the beginning/end of a sequence.
  • [CLS]: a summary token, often prepended so its final representation can be used for sequence-level classification.
  • [SEP]: separates two distinct segments packed into the same input (e.g., two sentences).
  • [MASK]: a placeholder for a hidden token, used when training masked language models.

Not every tokeniser uses all of these — it depends on how the model was trained.

Output

The output will be a vector of logits, a score for each possible token:

from transformers import AutoModelForCausalLM
from torch import no_grad

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2-0.5B")

prompt = "Once upon a"
input_ids = tokenizer(prompt, return_tensors="pt").input_ids
with no_grad():
    outputs = model(input_ids)

outputs.logits
tensor([[[ 7.9062,  4.9062,  1.9688,  ..., -4.5938, -4.6250, -4.6250],
         [ 5.3438,  4.7812,  0.4473,  ..., -6.3125, -6.3125, -6.3125],
         [ 2.5156,  3.3281,  0.7422,  ..., -6.4375, -6.4375, -6.4375]]],
       dtype=torch.bfloat16)

Output

This is more interpretable as a probability. We can make this conversion using the softmax function:

final_logits = outputs.logits[0,-1]
final_logits.softmax(dim=0)
tensor([1.6298e-07, 3.6694e-07, 2.7590e-08,  ..., 2.1032e-11, 2.1032e-11,
        2.1032e-11], dtype=torch.bfloat16)

We can find the most likely continuation using argmax:

predicted_logit = final_logits.argmax()  
tokenizer.decode(predicted_logit)
' time'

Qwen thinks that this is overwhelmingly likely to be the next token, with probability

final_logits.softmax(dim=0)[predicted_logit]
tensor(0.9766, dtype=torch.bfloat16)

Recall that \(\text{softmax}(\mathbf{z})_i = \frac{\exp(z_i)}{\sum_i\exp(z_i)}.\) These values must therefore be positive and sum to 1.

Decoding

To generate more than one token, we repeat this process: predict a next-token distribution, pick a token, append it, and feed the longer sequence back in.

Always picking the single most likely next token is called greedy search.

prompt = "Once upon a"
input_ids = tokenizer(prompt, return_tensors="pt").input_ids
with no_grad():
    output_ids = model.generate(input_ids, max_new_tokens=15, do_sample=False)
tokenizer.decode(output_ids[0])
'Once upon a time, there was a man who was very rich. He had a lot'

Greedy search is deterministic, but always taking the locally-best token can miss a better sequence overall, and tends to produce repetitive text.

Decoding

Instead of always taking the maximum, we can sample from the predicted distribution.

  • Temperature rescales the logits before the softmax: low temperature sharpens the distribution towards greedy behaviour, high temperature flattens it towards uniform (more random) sampling.
  • Top-\(k\) sampling restricts sampling to the \(k\) most likely tokens, discarding the long unlikely tail.
  • Top-\(p\) (nucleus) sampling instead keeps the smallest set of tokens whose cumulative probability reaches \(p\), adapting how many tokens are considered to how confident the model is.
with no_grad():
    output_ids = model.generate(
        input_ids, max_new_tokens=15,
        do_sample=True, temperature=0.8, top_k=50, top_p=0.9,
    )
tokenizer.decode(output_ids[0])
'Once upon a time, I was so afraid of making a mistake that I never even tried'

Decoding

Looking only at the next token might lead us to discard the start of a useful sentence.

Beam search considers the \(n\) most promising partial sequences (“beams”) and expand them all, finally returning the highest-scoring complete sequence.

  • More likely than greedy search to find a high-probability sequence overall.
  • Still deterministic and may give generic, repetitive text.
  • Costs roughly \(n\times\) the compute of greedy search, for \(n\) beams.
with no_grad():
    output_ids = model.generate(input_ids, max_new_tokens=15, num_beams=4, do_sample=False)
tokenizer.decode(output_ids[0])
'Once upon a time, there was a young man named John. He lived in a small'
