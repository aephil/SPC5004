From text to images

So far we have studied transformers, working with text. From today we turn to images, and to the models that generate them.

  • Autoencoders (today): compress an image down to a few numbers, and back again.
  • Variational autoencoders: make that compressed space something we can sample from.
  • Sparse autoencoders: the same idea turned back on a language model’s internals.
  • CLIP: text and images in one shared embedding space.
  • Diffusion: generate an image by removing noise step by step, first on pixels and then in an autoencoder’s compressed space. This is how Stable Diffusion works.

Transformers vs autoencoders

These two architectures have in common: an encoder and a decoder; a learned vector that represents the input, like an embedding; and gradient descent for training.

Transformers Autoencoders
Data discrete tokens: an \(n \times d\) matrix continuous pixels: a \(C \times H \times W\) tensor
Architecture attention convolutions
Loss cross-entropy over a vocabulary squared distance between pixel values
Labels pretraining needs none (the next token is in the text); our fine-tuning used labelled data none: the target is the input itself
Output one token at a time the whole image at once

Compression as a learning objective

An autoencoder learns to reproduce its own input, after squeezing it through a narrow bottleneck.

  • The encoder compresses the input \(x\) to a short latent vector \(z\).
  • The decoder reconstructs \(\hat x\) from \(z\) alone.
  • If \(\hat x\) is close to \(x\), then \(z\) must have kept whatever mattered about the input: a learned, lossy compression.

The shape of an autoencoder

Reconstruction loss

The training signal is how far the reconstruction is from the original: the squared difference, averaged over all the pixels.

\[\mathcal{L} = \lVert x - \hat x \rVert^2\]

  • Pixel values are continuous numbers, not choices from a vocabulary, so there is no softmax and no cross-entropy. We measure a distance instead.
  • Like next-token prediction, this needs no labels: it is self-supervised. What’s new is the target. It is not the next piece of the input, but the whole input itself.

Why the bottleneck?

  • If \(z\) were as big as \(x\), what would stop the network from simply copying its input? Would it learn anything useful?
  • The decoder sees only \(z\). Why not let it peek at the encoder’s earlier layers too?

We will return to both of these questions later: sparse autoencoders make \(z\) bigger than the input on purpose, and the network inside a diffusion model adds exactly those shortcuts.

Images as data

An image is a tensor

  • A greyscale MNIST digit is a \(1 \times 28 \times 28\) tensor: one channel, 28 rows and 28 columns, each value in \([0, 1]\).
  • A colour image has three channels (red, green and blue): \(3 \times H \times W\).
  • Compare a sentence, an \(n \times d\) matrix. Its tokens have neighbours along one dimension; an image’s pixels have neighbours along two.
  • PyTorch works on a whole batch of images at once, \(B \times C \times H \times W\): those are the shapes you’ll see in the lab.

Convolution

A convolution slides a small grid of learned weights, the kernel, across the image. A layer has many kernels, and each one produces one output channel.

Convolution vs. attention

Both mix information between positions. The network inside a diffusion model uses both.

The other ingredients

  • ReLU sets negative values to zero: a non-linearity, like the one in the transformer’s feed-forward layer.
  • Batch normalisation keeps activations at a sensible scale, like layer normalisation in the transformer block (but averaged over a batch).
  • A sigmoid at the very end squashes every output into \([0, 1]\), to match the pixel values of the real images.

You’ll see these in more detail in SPC5003. Here we only need to know what each one is for.

Training from scratch

Until now we have fine-tuned pretrained models with Trainer. This model is small enough to train from random weights in minutes, and we write the training loop ourselves:

for images, _ in train_loader:          # labels thrown away
    reconstructed = autoencoder(images)
    loss = F.mse_loss(reconstructed, images)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
  • The _ discards the digit labels: the target is images, the input itself.
  • loss.backward() works out the gradients and optimizer.step() takes one step of gradient descent: exactly what Trainer was doing for us.

Encoder-decoder, again

Not the encoder-decoder we’ve seen before

Attention was first used in translation to remove a bottleneck: older models squeezed the whole source sentence into one vector. An autoencoder puts the bottleneck back on purpose.

“Autoencoding” language models

In the first lecture we called encoder-only models like BERT autoencoding.

  • Masked language modelling corrupts the input by hiding some tokens, and trains the model to reconstruct it.
  • That’s a denoising autoencoder, but without a bottleneck: BERT keeps one vector per token throughout.
  • We’ll see lots more denoising later, when we get to diffusion models (and also in one of this week’s lab projects).

The latent space

Latent vectors are embeddings

  • \(z\) is a learned representation of the input, just like the token and sentence embeddings we’ve seen with transformers.
  • Images that look alike should land near each other in latent space.
  • The autoencoder never sees the digit labels. In the lab, you’ll colour each encoded point by its label afterwards. Will each digit form its own group?

How many latent dimensions?

With two latent dimensions, we can plot every encoded digit as a point. With 16 or 64 we can’t. What else changes?

In the lab, you’ll make a prediction: how sharp will the reconstructions be with 4, 16 or 64 latent dimensions? Why?

A vector, or a grid?

Stable Diffusion’s latent keeps its rows and columns, so the diffusion model can treat it like a small image.

Decoding points we never encoded

The decoder will accept any \(z\), not just one that came from a real image.

  • Encode two different digits, and decode the point halfway between them. What do you expect to see?
  • Pick a point where no image was ever encoded. What will the decoder make of it?
  • If you wanted brand-new digits, which values of \(z\) would you try?

These are the questions today’s lab ends on, and where Friday’s lecture begins.

Where this is heading

Inside Stable Diffusion

  • The text encoder is a transformer: CLIP’s text encoder.

  • The UNet has today’s shape (shrink, then grow back) plus shortcuts and attention, and it is trained to remove noise.
