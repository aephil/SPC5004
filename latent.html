Latent space

In lectures 11–14, we met four architectures: the autoencoder, the variational autoencoder, the sparse autoencoder and CLIP. Each one encodes its input as a point in a latent space. Because in each case we train using a different loss function, each builds a differently shaped space, useful for a different purpose.

What is a latent space?

  • An encoder turns an input $x$ into a vector $z$. We have met this idea before: token embeddings place words with similar meanings near each other.
  • $z$ is latent, meaning hidden: nobody labels it. Training decides what its coordinates mean, and where each input lands.
  • So the loss decides the shape of the space. The four architectures of lectures 11–14 use four different losses, and get four differently shaped spaces, each good for a different job.

Autoencoder: squeeze, then rebuild

  • The encoder compresses a 28 × 28 MNIST image, 784 numbers, into a short vector $z$. The decoder rebuilds the image, $\hat x$, from $z$ alone.
  • The loss is the mean squared error between $x$ and $\hat x$: a reconstruction loss. No labels are needed.
  • The narrow bottleneck is the point. The network can't copy its input through, so $z$ must keep what matters most about the image. This is lossy compression.
  • Fewer latent dimensions mean more compression, and blurrier reconstructions.
  • A real test digit through the lab's autoencoder with 16 latent dimensions. The bars are its 16 latent numbers.

Autoencoder: a space with holes

  • With only 2 latent dimensions, we can plot every test digit as a point. Similar digits land near each other, because that helps reconstruction.
  • But nothing in the loss mentions the space between the points. The clusters are uneven, and a point in a gap decodes to a smeared blend of digits.
  • With more latent dimensions it gets worse: there is far more room for holes. If we draw $z$ at random from $\mathcal N(0, 1)$ for the 16-dimensional autoencoder of step 2, the decoder will produce fragments. So an autoencoder compresses well, but can't make new digits.
  • 700 test digits, coloured by their label.

VAE: encode a cloud, not a point

  • In a variational autoencoder, the encoder outputs a mean $\mu$ and a standard deviation $\sigma$ for each latent dimension. Training decodes a random sample, $z = \mu + \sigma\epsilon$ with $\epsilon \sim \mathcal N(0, 1)$. Writing the sample this way (the reparameterisation trick) lets gradients reach $\mu$ and $\sigma$.
  • Each digit now covers a small cloud, so the neighbourhood of every point must decode sensibly too.
  • A second loss term, the KL divergence, measures how far each cloud is from $\mathcal N(0, 1)$, and pulls them all towards it. The loss is reconstruction + KL.
  • Each ellipse is one digit's $\mu \pm \sigma$, from the 2-D VAE.

VAE: sample and walk

  • The space is now filled, and centred on a known distribution. If we draw $z \sim \mathcal N(0, 1)$, the decoder should make a plausible digit: the VAE is generative.
  • Walking in a straight line between two codes morphs one digit smoothly into the other.
  • However, reconstruction has suffered. If we increase the weight of the KL term, the reconstructions get blurrier; if we decrease its weight, the holes come back.
  • Stable Diffusion uses a VAE in just this way, with a latent grid of 4 × 64 × 64 instead of a vector.

Sparse autoencoder: the same shape, flipped

  • We now apply an autoencoder to a language model's internals: the residual stream of GPT-2 small, where each token is a vector $x$ of $d = 768$ numbers.
  • The model represents far more than 768 concepts. Each seems to be a direction, overlapping with the others (superposition), so no single coordinate of $x$ means one thing.
  • A sparse autoencoder (SAE) makes $z$ much wider, 24,576 numbers, but forces it to be sparse: a ReLU plus an L1 or top-$k$ penalty leaves only a handful non-zero.
  • The loss function is similar to the VAE: loss = reconstruction + a term that shapes the latent space. Here the shape we want is “few active at once”.

SAE: features, and steering

  • The decoder is a dictionary: $\hat x = b_\mathrm{dec} + \sum_i z_i w_i$. Each active $z_i$ says how much of the direction $w_i$ a token contains. The pair is a feature, often interpretable on its own.
  • For “ dog” in “The dog barked at the cat in the garden”, 47 of the 24,576 features are active. The largest, 12435, fires on mentions of dogs. This is an observation of correlation.
  • Steering tests causation. We add a term in a specified direction, $x \leftarrow x + s\,w_i$, and see whether the output changes as predicted. “At the weekend, I like to”:
    strength 0: get my hair done. I'm not a big fan of …
    strength 16: keep my puppy and his crate under my bed. He's only 9 weeks, but he's been barking, barking,
  • So this latent space is for understanding a model, not for generating from it.

CLIP: one space for pictures and words

  • CLIP no longer needs a decoder, because there is nothing to reconstruct. Instead there are two encoders, a vision transformer for images and a text transformer for captions, each projected into the same latent space.
  • Contrastive training: in each batch of image–caption pairs, pull every image towards its own caption and push it away from the others. The loss is cross-entropy along the rows and columns of the batch's similarity matrix.
  • The vectors are normalised, so only their direction matters. A position in this space now means what the picture or text is about, in a form shared by both.

CLIP: compare by cosine

  • Closeness is cosine similarity. Real values are small (0.244 for the cat and its caption), so the ranking matters more than the value: each photo's own caption wins its row.
  • Zero-shot classification embeds one prompt per class and picks the closest, so new classes need no retraining. But softmax only shares probability among the options offered: “a photo of a cat” falls from 99.8% against one rival to 2.4% against five.
  • CLIP score, 100 × the cosine for one image and one prompt, will measure how well a generated image matches its prompt.
  • CLIP barely sees word order: “a dog chasing a cat” and “a cat chasing a dog” have cosine similarity 0.98.
