CLIP

Connecting words and pictures

So far, our models have kept text and images in separate worlds.

  • An autoencoder’s latent vector summarises an image, but says nothing about what it means in words.
  • An ordinary image classifier links images to words, but only to a fixed list of labels, and it needs someone to label its training data.
  • The web, though, is full of images with captions, for free.

CLIP (Contrastive Language–Image Pre-training) uses those captions to put images and text into one shared embedding space, where a picture and a good description of it lie close together.

A different architecture

CLIP is not an autoencoder. It has no decoder, and it never reconstructs anything.

  • We keep one idea: an encoder that turns its input into a vector. Now there are two.
  • An autoencoder’s vector must keep enough to redraw every pixel. CLIP’s only has to keep what a caption might mention.
  • The encoders are different too: they’re transformers, not convolutions.

The two towers

Two encoders, one space

  • There are two separate transformers, usually called towers, with no connection between them until the very end.
  • Their outputs have different sizes and mean different things, so a small linear projection maps each to the same 768-dimensional space.
  • Everything is trained together, from scratch. (These are the sizes of the model we’ll use in the lab.)

The image tower

A vision transformer (ViT) treats an image as a sequence of tokens: clip-vit-large-patch14 means ViT-Large with 14-pixel patches.

  • \(224/14 = 16\), so there are \(16 \times 16 = 256\) patches, each of \(14 \times 14 \times 3 = 588\) numbers.
  • A linear layer embeds each patch, and we add position embeddings. The rest is the same as when we studied text transformers.
  • An extra learned token, CLS, collects a summary. Its final vector is the pooler_output.

Why a transformer for images?

The image encoder doesn’t have to be a transformer. What makes a network an autoencoder is its decoder and its reconstruction loss, not the layers in its encoder. The CLIP authors tried both: 5 convolutional encoders and 3 ViTs.

  • A convolution sees a small neighbourhood, and the view widens layer by layer. With attention, any patch can use any other from the first layer.
  • Convolutions build in the assumption that nearby pixels belong together. That helps with little data, but matters less with hundreds of millions of images.
  • The ViTs were about 3 times more compute-efficient, so the best CLIP model is a ViT.

The text tower

Here is what the tokeniser makes of a caption:

<|startoftext|> a photo of a cat <|endoftext|>

  • This is a transformer much like GPT-2, with a limit of 77 tokens.
  • It uses a causal mask, so each token sees only those before it. Only the last token has seen the whole caption.
  • So the summary, pooler_output, is the final vector for <|endoftext|>: the same role as CLS in the image tower.

Contrastive training

The training game

CLIP’s task: in a batch of \(N\) (image, caption) pairs, match each image with its own caption.

Real values from the model we’ll use in the lab. Photos: scikit-image sample data (CC0 or public domain).

Pull together, push apart

  • Each diagonal entry is a positive pair: training pulls those two vectors together.
  • All the other entries are negatives, pushed apart. We don’t need to prepare these separately, since every other caption in the batch can be a wrong answer.
  • That’s why this is called contrastive learning: the model never has to produce a caption, only to tell the right one from the alternatives.

The loss is cross-entropy

Each row is a classification problem with \(N\) classes, where the right answer is on the diagonal. And so is each column.

import torch
import torch.nn.functional as F

similarities = torch.tensor([[0.244, 0.154, 0.126, 0.142],   # the matrix we just saw
                             [0.144, 0.228, 0.088, 0.124],
                             [0.108, 0.092, 0.238, 0.151],
                             [0.111, 0.095, 0.153, 0.199]])
logits = 100 * similarities
labels = torch.arange(4)                         # row i's answer is column i

loss_images = F.cross_entropy(logits, labels)    # each image picks a caption
loss_texts = F.cross_entropy(logits.T, labels)   # each caption picks an image
print(f"{(loss_images + loss_texts) / 2:.4f}")
0.0030

This is the same cross-entropy we used to train classification heads. A trained model gets these four almost perfectly right. A model guessing at random would score \(\ln 4 = 1.39\).

Scale

  • Data: 400 million (image, text) pairs from the web.
  • Batch size: 32,768. Each image must find its caption among 32,767 wrong ones, so guessing scores \(\ln 32768 = 10.4\).
  • Bigger batches mean more negatives, and so a harder game, which forces a finer description of each image.
  • Training: 32 epochs. The largest ViT took 12 days on 256 GPUs.

Why not simply train the model to generate each caption? That’s a harder task than we need, as there are many ways to caption any one image. The authors found the contrastive objective learned about four times faster than predicting the words of the caption, even as an unordered bag.

Why multiply by 100?

Take the rocket photo from our matrix. It scores 0.221 with “a rocket on the ground” and 0.203 with “a rocket in space”. Applying softmax directly:

\[\frac{e^{0.221}}{e^{0.221} + e^{0.203}} \approx 0.50\]

We met this problem with attention: cosines are too close together for softmax to separate them. So we scale them first:

\[\frac{e^{22.1}}{e^{22.1} + e^{20.3}} \approx 0.86\]

A learned temperature

  • This is the temperature we met when sampling text: dividing logits by \(\tau\). Multiplying by 100 means \(\tau = 0.01\).
  • In CLIP it is learned, not chosen by hand. It started at \(\tau = 0.07\), a factor of about 14, and was capped at a factor of 100 to keep training stable.
  • The model we’ll use in the lab ended up exactly at the cap, so its factor is simply 100.

Embedding-space geometry

Cosine similarity

Once embeddings are normalised to unit length, they are just points on a sphere, and comparing them needs only a dot product.

image_embed = torch.tensor([0.8, 0.6])
text_embed  = torch.tensor([0.9, 0.44])

torch.nn.functional.cosine_similarity(image_embed, text_embed, dim=0)
tensor(0.9822)

In this toy example, 1 means pointing the same way, and 0 means at right angles. Only the direction counts, not the length: that’s why we normalise.

But you won’t see values like this from real CLIP.

Real CLIP similarities are small

  • A good caption scores about 0.2 to 0.3, not close to 1. Images and captions occupy separate regions of the sphere, called the modality gap.
  • The loss only asks the right caption to beat the wrong ones, so nothing forces this gap to close.
  • So the ranking carries the information, and a difference of 0.03 can be decisive. Don’t read 0.22 as a “22% match”.

Zero-shot classification

A classifier with no training

A normal image classifier is trained against one fixed set of labels. CLIP sidesteps this entirely.

  • Embed the image once.
  • Embed a text prompt for each candidate class (e.g. "a photo of a cat", "a photo of a dog").
  • Pick the class whose text embedding is most similar to the image embedding.

New classes need no retraining, just new prompts. This is what zero-shot means here.

The best CLIP model reaches 76.2% on ImageNet this way, matching the original ResNet-50 without any of its 1.28 million labelled training images. (That version uses 336-pixel images; the one in the lab uses 224.)

Probabilities depend on the list

Softmax only shares out probability among the candidates we offer. Same photo, same model:

“A photo of a cat” falls from 99.8% to 2.4%, though its cosine similarity is still 0.244. It hasn’t become a worse answer: the list now has a better one.

These numbers mean “the best of these options”, not “how likely this is to be true”.

Prompts matter

The training captions were mostly phrases and sentences, not single words, so a bare label is unlike what CLIP has seen.

  • The cat photo above scores 0.229 with "a cat", but 0.244 with "a photo of a cat".
  • On ImageNet, the template "A photo of a {label}." improved accuracy by 1.3%. Averaging the embeddings of 80 different templates added another 3.5%.
  • The transformers library has a pipeline for this task. Its hypothesis_template argument sets the template: the default is "This is a photo of {}.".

What CLIP misses

  • Relations. For this photo, the false “a cup of coffee on a spoon” (0.200) narrowly beats the true “a spoon next to a cup of coffee” (0.197).
  • Word order. The text embeddings of “a dog chasing a cat” and “a cat chasing a dog” have cosine similarity 0.98. The matching game rarely needs this distinction, so CLIP barely learns it.

  • Text in the image. An apple with a label reading “iPod” can be classified as an iPod.
  • Bias. The web’s captions carry the web’s stereotypes. The CLIP paper itself reports harmful associations in its classification of photos of people.

CLIP score

Later in the module, when we generate images from text prompts, we’ll want to ask how faithfully a generated image matches its prompt.

The answer is the same recipe, scored for one image against one prompt rather than ranked against a list of candidates:

\[\text{CLIP score} = 100 \times \cos(\text{image}, \text{prompt})\]

  • This 100 is only a convention. It’s not the temperature, and there’s no softmax here.
  • The cat photo scores about 24 against “a photo of a cat”. Real similarities are small, so that shouldn’t alarm you!
  • CLIP score measures match to the prompt, not image quality. It’s most useful for comparing one image or model with another.

Summary

  • CLIP is not an autoencoder: it trains an image tower and a text tower together, so that images and their captions land close together in one space.
  • Training is a matching game: cross-entropy along the rows and columns of a batch’s similarity matrix.
  • Similarities are small, so a learned temperature scales them up, and ranking matters more than absolute value.
  • Zero-shot classification compares an image with a prompt for each class: new classes need only new prompts.
  • The same comparison, for a single image and prompt, gives us CLIP score.
